# MT19937 随机数预测模式

> 从已审核 writeup 提炼的通用解法模式，不含具体题目数据。

## 核心概念

MT19937 状态为 624 个 32 位整数，输出经**状态整型（tempering）**变换。只要拿到连续 624 个完整 32 位输出，即可逆变换（untemper）重建内部状态，从而预测后续所有输出。目标场景：题目用 Python `random` 生成密钥/填充/顺序，且把生成结果输出给了选手。

## 关键细节

- **输出变换**（temper）固定为四步：

```python
def temper(y):
    y ^= y >> 11
    y ^= (y << 7) & 0x9d2c5680
    y ^= (y << 15) & 0xefc60000
    y ^= y >> 18
    return y
```

- **逆变换**：每一步按位从高位向低位反推，四步颠倒顺序实现 `untemper`；注意 `(y << k) & mask` 型操作只影响低 32 位，需逐位构造。

```python
def untemper(y):
    y ^= y >> 18
    y ^= (y << 15) & 0xefc60000
    y ^= ((y << 7) & 0x9d2c5680) & 0xffffffff  # 逐位迭代实现更稳
    y ^= y >> 11
    return y
```

- **重建状态**：收集 624 个连续输出 → 逐个 `untemper` → 填入 `state[624]` → 用 `random.Random()` 构造并覆写 `rng.setstate((3, tuple(state + [624]), None))` → 此后 `rng.getrandbits(32)` 即与题目同步。
- **输出非完整 32 位**：`getrandbits(n)`（n<32）或 `randrange` 产生截断值时，直接凑 624 个不够；可用 Z3（BitVec 32）对已知输出建立约束，解出完整状态。

## 常见坑

- 输出必须来自**同一条连续流**；题目若把 `random` 混用于密钥与其它字段，需按调用顺序把截取段还原成完整 624 个 32 位块。
- `getrandbits(64)` 一次消耗两个 32 位状态字，计数时按两倍算。
- `setstate` 的第 2 个元素末位是索引 `pos`（通常 624），写错会立即产生不一致输出。
- Python 版本间 `random` 算法一致（均为 MT19937），但 `randrange`/`randint` 的取值方式在 3.2 后为拒绝采样，只影响取值范围不影响状态重建。

## 验证方式

- 重建后用预测值与题目给出的下一批输出比对，至少 3 项一致再用于解题。
- 若拿到的样本数不足 624，先用 Z3 解一个小子集（如 3–5 个约束）验证约束模型正确，再扩到全量。
- 本地用 `random.Random(seed)` 生成 624 个输出作自检：untemper → setstate → 预测与真实序列逐项相等。
