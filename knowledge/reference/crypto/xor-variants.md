# XOR 密码变体分析（通用模式）

> 从多份已审核 writeup 提炼的通用解法模式，不含具体题目数据。

## 识别阶段

1. 密文难以肉眼识别为文本、长度与明文字节数相同、字节分布平坦——优先怀疑 XOR/编码。
2. 观察密文是否与已知明文结构对齐（`flag{` 前缀、`\x00` 填充、重复字节模式）。
3. 单字节 XOR：`密文 ^ 'f'`（或任一已知明文字节）得到密钥，再全量解出验证可打印率。

## 变体与对应解法

- **单字节 XOR**：统计频率或已知明文求密钥；`bytes([b ^ key for b in data])` 全量尝试 256 个 key，按可打印比例/频率评分。
- **多字节 XOR（重复密钥）**：密钥长度未知时用重合指数或已知明文定长；每段做单字节 XOR 分析，或用 `xortool` 辅助定长。
- **密钥流复用（two-time pad）**：两条密文异或消除密钥得到 `m1 ^ m2`；结合已知明文片段（空格、`flag{`）向两侧扩展恢复。
- **流式 XOR 变种**（自增/自减密钥、密钥 += 固定量、逐块累加）：先求首字节密钥，再按生成规律递推后续字节；确认每步与 `flag{` 前缀匹配。
- **XOR 后接编码**：先还原 XOR 再解 base64/hex/ROT；顺序错误会导致无法解出，注意题目脚本的处理顺序。

## 标准解题步骤

1. 读取输出文件（注意题目给的 `output.txt` 可能是 hex/base64 文本，先解码为字节）。
2. 用已知明文前缀 `flag{` 求前若干密钥字节，验证与题目生成器（若有 `source.py`）的逻辑一致。
3. 写还原脚本时按**生成顺序的逆序**处理（后处理的先还原）。
4. 解出后检查是否整段可读（不是只有开头匹配）。

## 常见坑

- Python 字符串与 bytes 混用导致 XOR 类型错误：统一 `bytes`/`bytearray`。
- 密文文件是 hex 文本时忘记 `bytes.fromhex`，直接按字符 XOR。
- 多字节密钥的周期判断错误：用多个已知明文位置交叉验证周期，而不是只看前 2 字节。

## 验证方式

- 还原结果首尾完整可读且包含 flag 格式；用 `flag{` 位置做端到端自检。
- 若题目同时给出生成脚本，本地用生成脚本正反各跑一遍确认逻辑等价。
